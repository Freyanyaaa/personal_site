 # personal_site
This website is intended as a personal portfolio and an aggregate for me to document projects which i've worked on aswell as a means to display programming knowledge.
The intended audience for this website mainly consists of people who are interested in my projects and ability for whatever reasons.
These can include recruiters who seek to further understand my ability, other developers interested in what i've done or people who for another reason care.
This website is built upon a set of requirements and the project originates from a school assignment. 
I am required to list the requirements and explain how this site has met them:
1. Structure & Semantics
  - at minimum three pages. This is met because the site has more than 3 pages.
  - correct semantics such as header, nav, main, section, article, footer. All of these have been used correctly. The header is a header. The nav is a nav. The Article is an article.
2. Layout
 - Atleast one site built with Flexbox. At current, all pages make use of flexbox in the main-header div class. 
 - Atleast one site built with CSS Grid. At current, the navbar is built with CSS grid. Furthermore, the past project section on blog.html has a css grid with 4 previous pages.
 - Rational, readable CSS (Indentation and naming). The CSS is not word salad. the intro-article class is named intro article. the body class is body. the navbar is titled navbar.
3. Responsivity
 - Mobile-first with atleast two breakpoints. The website is designed to be dynamically scalable. i added two breakpoints to the previous projects tab to display that i am capable of using breakpoints.  
 - Responsive images and reasonable image sizes. This is achieved 
4. Typography & colour
 - headers have been used in order.
 - there is contrast.
 note: i am not a graphic designer and i do not have an eye for aesthetics.
5. Availability
 - alt texts for images, descriptive links. the images used are purely decorative. according to w3, decorative images shall have a null text alternative. links are self-explanatory. no mystery links here.
6. Forms
 - A simple contact page. Initially, contact was only through email. I did however add a form last-minute because i realized that it might be of necessity.
7. Publication
 - The site is published through github pages.
8. Quality
 - No dead code or broken links. There is no dead code and there are no broken links.
 - Logical folder structure. There is a logical folder structure. 
 - Optimized images. I am using a royalty free floppy disk and a low quality gif of lain iwakura from the hit anime Serial Experiments Lain dancing. These do not demand much bandwidth or processing power.
9. Code Validation
 - All code shall be validated iwth validator.w3.org and jigsaw.w3.org/css-validator. All code is validated with these.
 - Demand. 0 errors, warning tolerated if README explains why they can be ignored. There are no errors, comrade. There are no warnings to explore.

 Known shortcomings: The contact formula does not actually run any code at all and does not actually do anything. The header and footer must be manually updated across every page. There is no sync between new articles and what articles appear on the earlier projects grid.
